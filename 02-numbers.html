פרק 2 · ייצוג מספרים ופעולות אריתמטיות

log(x), לא x
זה גודל הקלט

למה ייצוג מספר בבסיס k דורש Θ(log x) ספרות, מה זה אומר על סיבוכיות, ושלושה אלגוריתמי כפל (נאיבי, רקורסיבי, Karatsuba).

האבחנה היחידה והחשובה ביותר בפרק הזה: כשהקלט הוא מספר טבעי x, גודל הייצוג שלו הוא log(x), לא x. לולאה שסופרת מ-x ל-0 רצה Θ(x) פעמים — שזה אקספוננציאלי בגודל הקלט. בכל ניתוח סיבוכיות שמערב מספרים, השאלה הראשונה היא: מה זה n? מספר האיברים, או אורך הייצוג?

קביעה חמורה למבחן: אלגוריתם "פולינומי" שאורך הביצוע שלו הוא poly(x) אבל גודל הקלט הוא log(x) — הוא אקספוננציאלי. תמיד תציין מה n מייצג.

ייצוג מספרים — כמה ספרות צריך?

📘בסיס עשרוני, בינארי, וכל k אחר

בסיס עשרוני — שימוש בספרות {0,...,9}. המספר 6379 פירושו:

$$6 \cdot 10^3 + 3 \cdot 10^2 + 7 \cdot 10^1 + 9 \cdot 10^0$$

כתבנו 4 ספרות, לא 6379. זוהי דרך קומפקטית לייצוג מספרים — חוסכת אקספוננציאלית בכמות הסימנים.

הכלל הכללי: אם הבסיס k > 1 קבוע (לא תלוי ב-x), אז מספר הספרות הנדרש לייצוג x הוא:

$$\Theta(\log_k x) = \Theta(\log x)$$

(לבסיסים שונים יש קבוע מכפלי בלבד — שאסימפטוטית לא משנה).

📐גודל קלט מול ערך הקלט — ההבחנה הקריטית

בכל בעיה אלגוריתמית שכוללת מספר טבעי x:

  • ערך הקלט: x עצמו (לדוגמה: 1000000)
  • גודל הייצוג: n = ⌈log₁₀(x)⌉ או log₂(x) בייצוג בינארי (לדוגמה: 7 ספרות עשרוניות, או 20 ביטים)

סיבוכיות נמדדת בגודל הייצוג, לא בערך:

  • אלגוריתם ב-O(n) = O(log x) — מצוין
  • אלגוריתם ב-O(x) = O(2^n) — אקספוננציאלי, לא יעיל

הנחות יסוד על מספרים

📘פעולות בסיסיות שמותר להניח

כשנכתוב אלגוריתמים על מספרים טבעיים, מניחים שנתונות לנו הפעולות הבאות על ספרות בודדות (או מילים של O(log n) ביטים) בזמן O(1):

  • חיבור +
  • חיסור −
  • כפל × (של מספרים קטנים)
  • חלוקה ÷ (של מספרים קטנים, עם שארית)
  • השוואה <, >, =

עבור מספרים גדולים (שהייצוג שלהם ארוך), חיבור וכפל הם פעולות שצריך לממש בעצמנו — וזה מה שהפרק עוסק בו.

חיבור מספרים גדולים

💡שיטה נאיבית מול שיטה אריתמטית

שיטת ה"גולות": נחבר את x ל-y ע״י לקיחת x גולות וגם y גולות וספירת כולן. זמן: Θ(x+y). זה אקספוננציאלי ב-n=log(x+y).

שיטת החיבור הארוך: פסאודו-קוד מהבסיס:

LONG-ADD(x[1..n], y[1..n]):  # ספרות מימין לשמאל
    r = 0  # carry
    for i = 1 to n:
        m = x[i] + y[i] + r
        if m < 10:
            z[i] = m;     r = 0
        else:
            z[i] = m - 10; r = 1
    if r = 1: z[n+1] = 1
    return z

סיבוכיות:

$$T(n) = \Theta(\log x + \log y)$$

זה לינארי בגודל הייצוג — אופטימלי.

📘הוכחת נכונות (סקיצה)

הוכחה באינדוקציה על n, מספר הספרות.

בסיס (n=1): שני מקרים:

  • אם x₁+y₁ < 10 — הפלט הוא x₁+y₁, נכון.
  • אם x₁+y₁ ≥ 10 — הפלט הוא 2 ספרות: (x₁+y₁) mod 10 והספרה השנייה 1. זה בדיוק הייצוג העשרוני של הסכום.

צעד אינדוקציה: הנח שהאלגוריתם נכון על מספרים באורך n−1. נסמן x'=x[1..n-1] ו-y'=y[1..n-1]. אזי:

$$x + y = (x_n + y_n) \cdot 10^{n-1} + (x' + y')$$

מהנחת האינדוקציה, האלגוריתם מחשב נכון את x'+y' ב-n−1 הספרות הראשונות, וה-carry שעובר לספרה ה-n בדיוק תואם ל-(x'+y') div 10^(n-1). הספרה האחרונה יוצאת (x_n + y_n + r) mod 10, נכון. ∎

כפל מספרים גדולים — שלוש גישות

גישה 1 — כפל נאיבי דרך חיבור

x·y מתקבל ע״י חיבור y לעצמו x פעמים. ביצועים: x פעולות חיבור, כל אחת ב-O(n). סך הכל O(x·n) = O(n · 2^n) — אקספוננציאלי.

גישה 2 — כפל ארוך ("מאונך")

השיטה מבית הספר: מכפילים ספרה-ספרה ומחברים. n × n מכפלות של ספרות + n חיבורים של מספרים באורך 2n. סך הכל Θ(n²). פולינומי אבל לא הכי מהיר.

גישה 3 — כפל רקורסיבי (לפני Karatsuba)

📘פירוק רקורסיבי לחצאים

נחלק את x ואת y לשני חצאים באורך n/2 ספרות:

$$x = a \cdot 10^{n/2} + b, \quad y = c \cdot 10^{n/2} + d$$

מתקיימת הזהות:

$$xy = ac \cdot 10^n + (ad + bc) \cdot 10^{n/2} + bd$$

זה דורש 4 כפלים רקורסיביים (ac, ad, bc, bd) של מספרים באורך n/2, פלוס 3 חיבורים ושני "כפלים בחזקות של 10" (זזוז סיביות).

📐ניתוח זמן הריצה

נוסחת הנסיגה:

$$T(n) = 4T(n/2) + \Theta(n)$$

פתרון לפי משפט האב (Master Theorem):

$$T(n) = \Theta(n^{\log_2 4}) = \Theta(n^2)$$

אכזבה: זה לא יותר טוב מהכפל המאונך הרגיל. ארבעת הכפלים הקטנים "אוכלים" את כל החיסכון.

גישה 4 — אלגוריתם Karatsuba

📐הטריק האלגברי

במקום 4 כפלים, נשתמש ב3 בלבד. הזהות המרכזית:

$$ad + bc = (a+b)(c+d) - ac - bd$$

נחשב רק שלושה כפלים: ac, bd, (a+b)(c+d). את ad+bc מקבלים בחיסור:

$$xy = ac \cdot 10^n + \bigl[(a+b)(c+d) - ac - bd\bigr] \cdot 10^{n/2} + bd$$
Karatsuba.txt 
KARATSUBA(x, y):  # x, y מספרים בני n ספרות
    if n = 1: return x*y          # מקרה בסיס
    a, b = split(x, n/2)           # x = a·10^(n/2) + b
    c, d = split(y, n/2)           # y = c·10^(n/2) + d
    z1 = KARATSUBA(a, c)
    z2 = KARATSUBA(b, d)
    z3 = KARATSUBA(a+b, c+d)
    return z1·10^n + (z3 - z1 - z2)·10^(n/2) + z2
📐ניתוח זמן הריצה של Karatsuba

נוסחת הנסיגה:

$$T(n) = 3T(n/2) + \Theta(n)$$

לפי משפט האב:

$$T(n) = \Theta(n^{\log_2 3}) \approx \Theta(n^{1.585})$$

הצלחה: מהר יותר מ-Θ(n²) משמעותית — לדוגמה, על מספרים של 1000 ספרות, פי כ-25 מהיר.

השוואת ארבעת האלגוריתמים על מספרים בני n ספרות:

תרגילים מהפרקטיקה

📝תרגיל 1 · practice1, שאלה 2 — סיבוכיות של "ירידה ל-0"
complexity · input-size analysis

לפניך קטע הקוד:

INPUT: x ∈ ℕ (בייצוג עשרוני)
while x > 0:
    x ← x - 1

א. תן חסם תחתון וחסם עליון (לאו דווקא זהים) לעלות איטרציה אחת (פעולת החיסור), כפונקציה של x. נמק.

ב. הוכח כי סיבוכיות הזמן של קטע הקוד היא Θ(x). רמז: חשבו כמה פעמים בסך הכל משתנה כל אחת מהספרות.

סעיף א · עלות איטרציה בודדת

פעולת x ← x − 1 בייצוג עשרוני דורשת מעבר על ספרות מהמשמעותית פחות (ימין). אם הספרה הימנית ≥ 1, מוריד 1 והכל מסתיים — O(1). אם הימנית = 0, צריך "לשאול" מהספרה הבאה, ואם גם היא 0 — ממשיכים שמאלה.

חסם תחתון: Ω(1) — לפחות פעולה אחת.

חסם עליון: O(log x) — לכל היותר עוברים על כל ספרות x, כלומר ⌊log₁₀ x⌋ + 1 ספרות.

למשל: x = 1000. החיסור צריך לשנות 4 ספרות (1000 → 0999) → O(log x).

סעיף ב · סיבוכיות סך-הכל

החסם הנאיבי: x איטרציות × O(log x) לכל אחת = O(x log x). אבל זה לא הדוק.

הטריק (מהרמז): נספור כמה פעמים כל ספרה משתנה לאורך כל הריצה:

  • הספרה הימנית (היחידות) משתנה בכל איטרציה → x פעמים.
  • ספרת העשרות משתנה רק כש-יחידות "עוברות" 0 → x/10 פעמים.
  • ספרת המאות משתנה x/100 פעמים.
  • ...
  • בכלל: ספרה במקום i משתנה x/10^i פעמים.

סך-כל שינויי הספרות לאורך כל הריצה:

$$\sum_{i=0}^{\log_{10} x} \frac{x}{10^i} = x \cdot \sum_{i=0}^{\infty} \frac{1}{10^i} \leq x \cdot \frac{10}{9}$$

זוהי סדרה גיאומטרית שמתכנסת לקבוע × x. סך הזמן: Θ(x). ∎

הזמן הוא Θ(x) — לא Θ(x log x). החסם ההדוק מתקבל מסיכום סדרה גיאומטרית, לא מהכפלת הגרוע ביותר. הערה חשובה: Θ(x) = Θ(2^n) כאשר n = log x — האלגוריתם אקספוננציאלי בגודל הקלט.
📝תרגיל 2 · practice1, שאלה 3 — בדיקת חלוקה ללא שארית
algorithm correctness + complexity

הגדרה: n מתחלק ב-a אם קיים טבעי k כך ש-n = ka.

נתון האלגוריתם:

DIV-CHECK(n, a):
    r = n
    while r > 0:
        r = r - a
    if r = 0: return YES
    else:     return NO

א. הוכח את נכונות האלגוריתם.

ב. מהי סיבוכיות הזמן? נמק.

שלב 1 · הוכחת נכונות (סעיף א)

טענת אינווריאנט: בכל איטרציה, r ≡ n (mod a) — כלומר השארית של r בחלוקה ב-a שווה לשארית של n בחלוקה ב-a.

  • בסיס: בהתחלה r = n, אז r ≡ n (mod a) טריוויאלית.
  • צעד: אם r ≡ n (mod a), אז גם r − a ≡ n (mod a) (חיסור כפולה של a לא משנה שארית). ✓

תנאי עצירה: הלולאה נעצרת כש-r ≤ 0. נראה ש-r = 0 בעצירה אם״ם a | n:

  • אם a | n אז n = ka, ואחרי k איטרציות r = 0 בדיוק.
  • אם a ∤ n, אז יש שארית חיובית 0 < m < a. לאחר איטרציה כשמגיעים ל-r = m, איטרציה נוספת תוריד אותו ל-m − a < 0 ונעצור עם r < 0 ≠ 0.
שלב 2 · סיבוכיות (סעיף ב)

מספר האיטרציות: ⌈n/a⌉. בכל איטרציה חיסור של מספרים באורכים O(log n) = O(log n) זמן.

סך הכל:

$$T(n, a) = O\!\left(\frac{n}{a} \cdot \log n\right)$$

במונחי גודל הקלט N = log n + log a:

$$T = O\!\left(\frac{2^N}{a} \cdot N\right)$$

זה אקספוננציאלי בגודל הקלט.

זה אלגוריתם איטי: במספרים גדולים שווה לחלק "במאונך" ב-O(log² n), או להשתמש ב-mod שמובנה.

(א) האלגוריתם נכון בעזרת אינווריאנט שמירת שארית. (ב) סיבוכיות O((n/a) · log n) — אקספוננציאלית בגודל הקלט. שוב הלקח מתרגיל 1: n כערך הוא אקספוננציאלי ב-log n שהוא גודל הייצוג.

⚠הטעות הגדולה

שלוש שאלות שמצוטטות פעם אחר פעם במבחן:

  1. "האלגוריתם רץ ב-O(n)" — מה זה n? אם זה ערך הקלט, האלגוריתם אקספוננציאלי בגודל הייצוג. אם זה מספר הספרות, האלגוריתם פולינומי.
  2. חלוקת ערכים שונים בעולם של גדלים שונים. מספר באורך 1024 ביטים מבטא ערך עד 2^1024 ≈ 10^308. ספירה עד שם בלוופ "פשוט" אינה אפשרית.
  3. Karatsuba מדגים שגם עבור פעולות "פשוטות", יש מקום לאלגוריתמיקה. ה-O(n²) הנאיבי לא בהכרח אופטימלי.
