תכנות דינמי

חמשת השלבים של DP, ושני יישומים קלאסיים: מקדמים בינומיים ובעיית התרמיל (knapsack).

תכנות דינמי הוא שיטה, לא אלגוריתם. כשבעיה ניתנת לפירוק לתתי-בעיות שמתחפפות, DP בונה את הפתרון מהקטן לגדול תוך שמירת תוצאות ביניים בטבלה. שני סימנים שבעיה מתאימה ל-DP: (1) מבנה אופטימלי — פתרון אופטימלי לבעיה מורכב מפתרונות אופטימליים לתת-בעיות; (2) תת-בעיות חופפות — אותה תת-בעיה נפתרת שוב ושוב. זה הופך אלגוריתם רקורסיבי אקספוננציאלי לאלגוריתם דינמי פולינומי.

על המבחן: שאלת DP טיפוסית — נתון בעיה לא-מוכרת, צריך לגלות את הרקורסיה ולתאר את הטבלה. השלבים הסטנדרטיים הם תמיד אותם 5. תרגול עם knapsack ועם LCS חיוני.

חמשת השלבים של DP

📐תהליך עבודה — תמיד באותו סדר
  1. הגדר את תת-הבעיה: מה הפרמטרים שמייחדים תת-בעיה? נסמן OPT(i, j, ...) את הפתרון האופטימלי לתת-הבעיה.
  2. כתוב נוסחת רקורסיה: כיצד OPT מורכב מתת-בעיות קטנות יותר?
  3. הגדר תנאי קצה (base case): מה הערך של תת-הבעיה הכי קטנה?
  4. מלא את הטבלה bottom-up: בסדר שמבטיח שכשמחשבים OPT(i,j), כל התלויות שלו כבר חושבו.
  5. שחזר את הפתרון: לרוב הטבלה נותנת רק ערך אופטימלי — לשחזור הפתרון עצמו צריך טיול אחורה דרך הטבלה.

יישום 1 — מקדמים בינומיים C(n,k)

💡הבעיה

הגדרה: C(n, k) = מספר הדרכים לבחור k פריטים מתוך n.

נוסחה רקורסיבית: כל פריט בחירה — או נכלל או לא:

$$C(n, k) = C(n-1, k-1) + C(n-1, k)$$

תנאי קצה: C(n, 0) = C(n, n) = 1.

אלגוריתם רקורסיבי נאיבי:

C(n, k):
    if k = 0 or k = n: return 1
    return C(n-1, k-1) + C(n-1, k)

סיבוכיות: O(2ⁿ) — עץ רקורסיה גדל אקספוננציאלית.

אלגוריתם DP:

C-DP(n, k):
    for i = 0 to n:
        C[i, 0] = 1
        C[i, i] = 1
    for i = 2 to n:
        for j = 1 to min(i-1, k):
            C[i, j] = C[i-1, j-1] + C[i-1, j]
    return C[n, k]

סיבוכיות: O(n · k) בזמן ובזיכרון. ניתן לשפר לזיכרון O(k) ע״י שמירת רק שורה קודמת.

יישום 2 — סדרה חלקית משותפת ארוכה ביותר (LCS)

💡הבעיה

קלט: שתי מחרוזות X = x₁x₂...xₘ ו-Y = y₁y₂...yₙ.

פלט: הסדרה הארוכה ביותר שמופיעה כתת-סדרה (לא בהכרח רציפה) בשתי המחרוזות.

דוגמה: X = "ABCBDAB", Y = "BDCAB". LCS אפשרי: "BCAB" או "BDAB" — שניהם באורך 4.

📘נוסחת הרקורסיה

נסמן L(i, j) = אורך LCS של x₁...xᵢ ו-y₁...yⱼ.

שתי אפשרויות בהינתן הזוג (xᵢ, yⱼ):

  • אם xᵢ = yⱼ: שני התווים שווים, נצרף אותם ל-LCS. L(i, j) = L(i-1, j-1) + 1.
  • אחרת: ה-LCS לא יכול לכלול גם xᵢ וגם yⱼ בו-זמנית. L(i, j) = max(L(i-1, j), L(i, j-1)).

תנאי קצה: L(0, j) = L(i, 0) = 0 לכל i, j.

LCS.txt 
LCS-DP(X, Y):
    m = length(X), n = length(Y)
    for i = 0 to m: L[i, 0] = 0
    for j = 0 to n: L[0, j] = 0
    for i = 1 to m:
        for j = 1 to n:
            if X[i] = Y[j]:
                L[i, j] = L[i-1, j-1] + 1
            else:
                L[i, j] = max(L[i-1, j], L[i, j-1])
    return L[m, n]

יעילות: O(m · n) בזמן ובזיכרון

שחזור ה-LCS עצמו: טיול אחורה מ-L[m, n]: אם X[i] = Y[j], הוסף את התו לפתרון וזוז ל-(i-1, j-1); אחרת זוז לאחד מ-(i-1, j) או (i, j-1) לפי הגדול.

יישום 3 — בעיית התרמיל (Knapsack, 0/1)

💡הבעיה

קלט: n פריטים. לכל פריט i נפח vᵢ וערך aᵢ. תרמיל בעל קיבולת W.

פלט: תת-קבוצה של פריטים בעלי נפח כולל ≤ W וערך כולל מקסימלי.

שים לב: זו בעיה NP-קשה במקרה הכללי. ה-DP הזה הוא פסאודו-פולינומי — פולינומי בנפח W, אבל W יכול להיות אקספוננציאלי בגודל הקלט.

📘נוסחת הרקורסיה

נסמן OPT(i, w) = ערך מקסימלי שאפשר להשיג עם i פריטים ראשונים ונפח לכל היותר w.

שתי אפשרויות עבור פריט i:

  • לא לוקחים את i: OPT(i, w) = OPT(i-1, w)
  • לוקחים את i (אם vᵢ ≤ w): OPT(i, w) = aᵢ + OPT(i-1, w - vᵢ)

הנוסחה:

$$OPT(i, w) = \begin{cases} OPT(i-1, w) & v_i > w \\ \max\{OPT(i-1, w), a_i + OPT(i-1, w - v_i)\} & v_i \leq w \end{cases}$$

תנאי קצה: OPT(0, w) = 0 לכל w.

Knapsack-DP.txt 
KNAPSACK-DP(items, W):
    for w = 0 to W:
        OPT[0, w] = 0
    for i = 1 to n:
        for w = 0 to W:
            if v[i] > w:
                OPT[i, w] = OPT[i-1, w]
            else:
                OPT[i, w] = max(OPT[i-1, w], a[i] + OPT[i-1, w - v[i]])
    return OPT[n, W]

יעילות: O(n · W) בזמן ובזיכרון

חישוב לדוגמה:

  • OPT[2, 5] = max(OPT[1, 5], 4 + OPT[1, 2]) = max(3, 4 + 3) = 7 — לקחנו את פריט 2.
  • OPT[4, 10] = max(OPT[3, 10], 6 + OPT[3, 5]) = max(12, 6 + 7) = 13 — לקחנו את פריט 4.

פתרון אופטימלי: OPT[4, 10] = 13

שחזור הפריטים:

  • i=4, w=10: OPT[4,10]=13 ≠ OPT[3,10]=12 ← לקחנו את 4. w = 10 − 5 = 5.
  • i=3, w=5: OPT[3,5]=7 = OPT[2,5]=7 → לא לקחנו את 3.
  • i=2, w=5: OPT[2,5]=7 ≠ OPT[1,5]=3 ← לקחנו את 2. w = 5 − 3 = 2.
  • i=1, w=2: OPT[1,2]=3 ≠ OPT[0,2]=0 ← לקחנו את 1. w = 2 − 2 = 0.

פריטים נבחרים: {1, 2, 4}. סכום נפחים: 2 + 3 + 5 = 10 ≤ W ✓. סכום ערכים: 3 + 4 + 6 = 13 ✓.

שחזור הפריטים שנבחרו

RECONSTRUCT(OPT, items, W):
    i = n
    w = W
    chosen = ∅
    while i > 0 and w > 0:
        if OPT[i, w] ≠ OPT[i-1, w]:
            chosen = chosen ∪ {i}
            w = w - v[i]
        i = i - 1
    return chosen

תרגיל מהפרקטיקה

📝תרגיל · תזמון קטעים ממושקלים
DP · weighted interval scheduling

נתונים n משימות. לכל משימה i: זמן התחלה sᵢ, זמן סיום fᵢ, ורווח vᵢ > 0. שתי משימות נחשבות מתנגשות אם זמני הביצוע שלהן חופפים. מצא תת-קבוצה של משימות שאינן מתנגשות ובעלת רווח כולל מקסימלי.

שלב 1 · הכנה

נמיין את המשימות לפי fᵢ בסדר עולה. נגדיר p(i) = המשימה הגדולה ביותר j < i כך ש-fⱼ ≤ sᵢ (האחרונה שלא מתנגשת עם i).

שלב 2 · רקורסיה

נגדיר OPT(i) = הרווח המקסימלי מ-i המשימות הראשונות. אפשרויות עבור משימה i:

  • לא לוקחים: OPT(i) = OPT(i-1)
  • לוקחים: OPT(i) = vᵢ + OPT(p(i))
$$OPT(i) = \max\{OPT(i-1), \; v_i + OPT(p(i))\}$$

תנאי קצה: OPT(0) = 0.

שלב 3 · יעילות

מיון: O(n log n). חישוב p(i): O(n log n) בעזרת חיפוש בינארי. מילוי טבלה: O(n). סה״כ: O(n log n).

DP על סדר זמני סיום הופך בעיה NP-קשה לכאורה (תזמון) לאלגוריתם O(n log n). הטריק: ממיינים לפי f, ובכל שלב מחליטים "ליטול או לא" — בדומה ל-knapsack.

מתי DP מתאים ומתי לא

⚠בחירת השיטה

סימנים ש-DP מתאים:

  • פתרון רקורסיבי טבעי, אבל אקספוננציאלי.
  • תת-בעיות חופפות (אותה תת-בעיה נקראת שוב ושוב).
  • תכונת "מבנה אופטימלי" — פתרון אופטימלי מורכב מפתרונות אופטימליים לתת-בעיות.

סימנים שצריך גישה אחרת:

  • אם חמדני עובד (וקל להוכיח שעובד) — חמדני זול יותר ב-זיכרון.
  • אם הבעיה NP-קשה ואין מבנה אופטימלי — DP פסאודו-פולינומי לא מספיק, צריך הקירוב.

מה לזכור למבחן

📌סיכום
  • חמשת השלבים: הגדר תת-בעיה, רקורסיה, base, מילוי, שחזור.
  • סימנים: תת-בעיות חופפות + מבנה אופטימלי.
  • דוגמאות בקורס: מקדמים בינומיים O(nk), knapsack O(nW), interval scheduling O(n log n).
  • פסאודו-פולינומי: knapsack תלוי ב-W, שגודלו בייצוג יכול להיות לוגריתמי.
  • חיסכון בזיכרון: לעיתים אפשר לעבור מ-O(n²) ל-O(n) בזיכרון על-ידי שמירה של שורה קודמת בלבד.
